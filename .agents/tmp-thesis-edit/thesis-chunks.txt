# **บทคัดย่อ**

การคัดแยกขยะขวดพลาสติกในสถานศึกษาส่วนใหญ่ยังขาดการบันทึกข้อมูลที่เป็นระบบ และขาดแรงจูงใจให้ผู้ใช้งานมีส่วนร่วมอย่างต่อเนื่อง ส่งผลให้ผู้ดูแลระบบไม่สามารถติดตามปริมาณและประเภทขยะได้อย่างมีประสิทธิภาพ งานวิจัยนี้จึงมีวัตถุประสงค์เพื่อพัฒนาเว็บแอปพลิเคชันต้นแบบ "EcoBin Connect" สำหรับบริหารจัดการข้อมูลการคัดแยกขยะประเภทขวดพลาสติก กรณีศึกษามหาวิทยาลัยราชภัฏเพชรบูรณ์ เพื่อประเมินประสิทธิภาพของระบบในการจัดเก็บข้อมูลและประมวลผลค่าคาร์บอนฟุตพริ้นท์ และเพื่อศึกษาความพึงพอใจของผู้ใช้งานต่อการใช้งานระบบ

ระบบถูกออกแบบให้รองรับผู้ใช้งาน 3 กลุ่ม ได้แก่ ผู้ดูแลระบบ สมาชิกทั่วไป และผู้ใช้งานแบบไม่ลงทะเบียน โดยสมาชิกสามารถสมัครเข้าสู่ระบบ ถ่ายภาพหรืออัปโหลดภาพขวดพลาสติก ติดตามสถิติและแต้มสะสม รวมถึงแลกของรางวัลได้ ส่วนผู้ดูแลระบบสามารถตรวจสอบภาพถ่าย จัดการบัญชีผู้ใช้และแคตตาล็อกของรางวัล รวมทั้งเรียกดูรายงานสถิติภาพรวมได้ การพัฒนาใช้ Next.js (React) และ Tailwind CSS ในส่วนติดต่อผู้ใช้ พัฒนา REST API ด้วยภาษา Go จัดเก็บข้อมูลด้วย MySQL บน Google Cloud SQL และเผยแพร่ผ่าน Vercel กับ Cloud Run

ผลจากการพัฒนาระบบทำให้ได้เครื่องมือต้นแบบที่ช่วยบันทึกและติดตามข้อมูลการคัดแยกขยะได้อย่างเป็นระบบ สร้างแรงจูงใจผ่านแต้มสะสมและการแลกของรางวัล และสนับสนุนนโยบาย Green University ของมหาวิทยาลัย นอกจากนี้ยังช่วยเพิ่มทักษะของผู้พัฒนาด้านการพัฒนาเว็บแอปพลิเคชัน การวิเคราะห์ออกแบบระบบ และการจัดการฐานข้อมูลบนคลาวด์

# **Abstract**

Plastic bottle sorting in educational institutions often lacks systematic data recording and sufficient incentives for continuous participation, making it difficult for administrators to monitor waste volume and types effectively. This research aimed to develop a prototype web application, EcoBin Connect, for managing plastic bottle sorting data, using Phetchabun Rajabhat University as a case study; to evaluate the system's effectiveness in data storage and carbon footprint calculation; and to study user satisfaction regarding usability and environmental awareness.

The system supports three user groups administrators, members, and unregistered (guest) users. Members can register and sign in, capture or upload plastic bottle images, view personal statistics and points, and redeem rewards. Administrators can verify submitted images, manage user accounts and the reward catalog, and view overall statistical reports. The system was developed using Next.js (React) and Tailwind CSS for the user interface, Go for the REST API, MySQL on Google Cloud SQL for data storage, and was deployed on Vercel and Cloud Run.

The developed prototype provides a practical tool for recording and monitoring plastic bottle sorting data, motivates users through a points-and-rewards mechanism, and supports the university's Green University policy. It also enhances the developers' skills in web application development, system analysis and design, and cloud-based database management.

## **1.1 ความสำคัญและที่มาของปัญหาของวิจัย**

ปัจจุบันสถานการณ์ปัญหาสิ่งแวดล้อมจากขยะมูลฝอยกำลังทวีความรุนแรงขึ้นอย่างต่อเนื่อง โดยมีสาเหตุสำคัญมาจากการขาดกระบวนการคัดแยกขยะที่ถูกต้องตั้งแต่ต้นทาง และขาดการบันทึกจัดเก็บข้อมูลการทิ้งขยะที่เป็นระบบ ซึ่งส่งผลให้ผู้คนขาดความตระหนักรู้และที่สำคัญคือ \"ขาดแรงจูงใจ\" ในการปรับเปลี่ยนพฤติกรรม ประกอบกับระบบบริหารจัดการขยะในระดับชุมชนหรือองค์กรยังขาดฐานข้อมูลเชิงสถิติที่ชัดเจน ทำให้ผู้ดูแลระบบไม่ทราบถึงปริมาณและประเภทของขยะที่เกิดขึ้นจริงในแต่ละพื้นที่ การจัดเก็บข้อมูลด้วยวิธีการแบบดั้งเดิมมักมีความยุ่งยากและตรวจสอบหลักฐานได้ยาก จึงมีความจำเป็นที่จะต้องนำเทคโนโลยีสารสนเทศที่ทุกคนใช้ในชีวิตประจำวันมาประยุกต์ใช้ เพื่อยกระดับการรวบรวมข้อมูลให้มีประสิทธิภาพและสร้างระบบกระตุ้นการมีส่วนร่วม

ด้วยเหตุผลดังกล่าว ผู้วิจัยจึงได้พัฒนา "EcoBin Connect" ซึ่งเป็นเว็บแอปพลิเคชันต้นแบบสำหรับบันทึกและจัดเก็บข้อมูลการคัดแยกขยะ โดยประยุกต์ใช้สมาร์ตโฟนเป็นเครื่องมือที่ใช้ในการทำงาน ระบบถูกออกแบบให้ผู้ใช้งานสามารถใช้กล้องสมาร์ตโฟนถ่ายภาพขยะเข้าสู่ระบบ เพื่อให้ระบบทำการตรวจสอบว่าเป็นขยะประเภท \"ขวดพลาสติก\" หรือไม่ หากข้อมูลถูกต้องระบบจะบันทึกผลและเพิ่ม \"แต้มสะสม\" ให้กับบัญชีผู้ใช้งานเพื่อเป็นแรงจูงใจ แต่หากภาพขยะไม่ถูกต้องระบบจะแสดงการแจ้งเตือนข้อผิดพลาดทันที นอกจากนี้ เว็บแอปพลิเคชันยังได้รวมระบบแคตตาล็อกของรางวัล (ในระดับเวอร์ชันทดสอบ V.0.1) ที่เปิดให้ผู้ใช้งานสามารถตรวจสอบคะแนนและกดทดสอบระบบการแลกของรางวัลได้ เพื่อจำลองรูปแบบการให้ผลตอบแทนจากการคัดแยกขยะอย่างเป็นรูปธรรม

สรุป งานวิจัยนี้มุ่งเน้นการพัฒนาเว็บแอปพลิเคชันบนอุปกรณ์เคลื่อนที่เพื่อเป็นเครื่องมืออำนวยความสะดวกในการจัดเก็บข้อมูลขยะต้นแบบ โดยมีจุดเด่นสำคัญคือความเรียบง่ายในการใช้งานที่อาศัยเพียงสมาร์ตโฟนในการส่งข้อมูล และการดึงดูดผู้ใช้งานด้วยระบบสะสมแต้ม ผลลัพธ์จากการพัฒนาระบบนี้ ไม่เพียงแต่จะช่วยสร้างแรงจูงใจและบันทึกประวัติการคัดแยกขยะขวดพลาสติกให้แก่ผู้ใช้งาน แต่ยังทำหน้าที่เป็นฐานข้อมูลสำคัญที่รวบรวมสถิติเชิงประจักษ์ เพื่อให้ผู้ดูแลระบบสามารถเรียกดูข้อมูลและนำไปใช้ประกอบการวางแผนบริหารจัดการขยะในพื้นที่ได้อย่างถูกต้องและมีประสิทธิภาพต่อไป

## **1.2 วัตถุประสงค์ของโครงการวิจัย**

###  1.2.1 เพื่อพัฒนาเว็บแอปพลิเคชันต้นแบบสำหรับการบริหารจัดการข้อมูลขยะประเภทขวดพลาสติก บนระบบปฏิบัติการ Android และ iOS 

###  1.2.2 เพื่อประเมินประสิทธิภาพของระบบสารสนเทศในการจัดเก็บข้อมูลการคัดแยกขยะ และการประมวลผลค่าคาร์บอนฟุตพริ้นท์ 

1.2.3 เพื่อศึกษาความพึงพอใจของผู้ใช้งานที่มีต่อเว็บแอปพลิเคชัน ในด้านความสะดวกในการใช้งานและการส่งเสริมความตระหนักรู้ด้านสิ่งแวดล้อม

## **1.3 ขอบเขตเนื้อหาในการวิจัย**

ระบบสารสนเทศการจัดการโครงงานวิจัย กรณีศึกษา สาขาวิชาวิทยาการคอมพิวเตอร์และสาขาวิชาเทคโนโลยีสารสนเทศ มหาวิทยาลัยราชภัฏเพชรบูรณ์

มีขอบเขตการดำเนินงานแบ่งตามผู้เกี่ยวข้องกับระบบ เป็น 2 ส่วน ดังนี้

###  1.4.1 ผู้ดูแลระบบ 

1.4.1.1 จัดการข้อมูลบัญชีผู้ใช้งานในระบบ

1.4.1.2 ตรวจสอบและยืนยันความถูกต้องของข้อมูลภาพถ่ายขยะขวดพลาสติก

1.4.1.3 จัดการข้อมูลรายการของรางวัล (เพิ่ม ลบ แก้ไขข้อมูลแคตตาล็อก)

1.4.1.4 เรียกดูรายงานสถิติปริมาณขยะขวดพลาสติกภาพรวม

1.4.1.5 เรียกดูรายงานสถิติการสะสมแต้มและการทดสอบแลกของรางวัล

###  1.4.2 สมาชิกทั่วไป 

1.4.2.1 สมัครสมาชิกและเข้าสู่ระบบ

1.4.2.2 ถ่ายภาพและอัปโหลดข้อมูลขยะประเภทขวดพลาสติกเข้าสู่ระบบ

1.4.2.3 รับการแจ้งเตือนผลการตรวจสอบ

1.4.2.4 เรียกดูหน้ากระดานสรุปผลเพื่อดูสถิติการคัดแยกขยะของตนเอง

1.4.2.5 เรียกดูจำนวนแต้มสะสมปัจจุบัน

1.4.2.6 เรียกดูรายการของรางวัลและกดทำรายการแลกของรางวัล

###  1.4.3 ผู้ใช้งานแบบไม่ลงทะเบียน 

1.4.3.1 เข้าสู่เว็บแอปพลิเคชันโดยไม่ต้องสมัครสมาชิก

1.4.3.2 เรียกดูข้อมูลรายการของรางวัลในระบบเบื้องต้น

## **1.6 นิยามศัพท์เฉพาะ**

1.6.1 เว็บแอปพลิเคชัน EcoBin Connect หมายถึง เว็บแอปพลิเคชันบนสมาร์ตโฟนที่พัฒนาขึ้นเพื่อใช้บันทึกภาพ ตรวจสอบประเภทขยะ และจัดเก็บสถิติการคัดแยกขยะ

1.6.2 ขยะประเภทขวดพลาสติก หมายถึง บรรจุภัณฑ์ขวดพลาสติก (เช่น PET หรือ HDPE) ที่เว็บแอปพลิเคชันกำหนดให้ผู้ใช้ถ่ายภาพเพื่อรับแต้มสะสม

1.6.3 ระบบสะสมแต้ม หมายถึง กลไกให้คะแนนเพื่อสร้างแรงจูงใจ เมื่อผู้ใช้อัปโหลดภาพขวดพลาสติกเข้าสู่ระบบได้อย่างถูกต้อง

1.6.4 ระบบแลกของรางวัล หมายถึง ส่วนแสดงรายการของรางวัลที่ผู้ใช้สามารถนำแต้มสะสมมาใช้แลกเปลี่ยนได้

1.6.5 ผู้ใช้งาน หมายถึง ผู้ที่เข้าใช้งานเว็บแอปพลิเคชัน EcoBin Connect เพื่อบันทึกข้อมูลการคัดแยกขยะของตนเอง

1.6.6 ผู้ดูแลระบบ หมายถึง ผู้จัดการระบบหลังบ้าน มีหน้าที่ตรวจสอบความถูกต้องของภาพถ่าย จัดการข้อมูลผู้ใช้ และดูสถิติการทิ้งขยะภาพรวม

## **1.7 ประโยชน์ที่คาดว่าจะได้รับ**

ประโยชน์ที่ได้รับจากการทำระบบเว็บแอปพลิเคชันคัดแยกขยะ (EcoBin Connect) มีดังนี้

###  1.7.1 ประโยชน์ต่อองค์กรและชุมชน

1.7.1.1 ง่ายต่อการบันทึกและเรียกดูข้อมูลสถิติการคัดแยกขยะขวดพลาสติกของคนในชุมชน

1.7.1.2 ช่วยสร้างแรงจูงใจในการคัดแยกขยะที่ถูกต้องให้กับผู้ใช้งาน ผ่านระบบสะสมแต้มและแลกของรางวัล

1.7.1.3 เพิ่มประสิทธิภาพให้ผู้ดูแลระบบในการวางแผนจัดเก็บขยะ ด้วยการเรียกดูฐานข้อมูลปริมาณขยะได้อย่างสะดวกรวดเร็ว

1.7.1.4 สนับสนุนนโยบายการจัดการสิ่งแวดล้อม (Green University) โดยใช้เทคโนโลยีสารสนเทศเข้ามาช่วยลดขั้นตอนความยุ่งยากในการเก็บรวบรวมข้อมูลแบบดั้งเดิม

###  1.7.2 ประโยชน์ต่อผู้พัฒนา

1.7.2.1 พัฒนาทักษะการเขียนโปรแกรมและการพัฒนาเว็บแอปพลิเคชัน

ผู้พัฒนาจะได้ฝึกฝนทักษะในการเขียนโปรแกรมด้วยภาษา TypeScript, Golang และการใช้ Next.js (React), Tailwind CSS ในการสร้างเว็บแอปพลิเคชันที่รองรับการใช้งานจริงบนอุปกรณ์เคลื่อนที่

1.7.2.2 ฝึกการวิเคราะห์และออกแบบระบบ

ผู้พัฒนาจะได้เรียนรู้กระบวนการวิเคราะห์ความต้องการของผู้ใช้งาน การออกแบบส่วนติดต่อผู้ใช้งาน (UI/UX) และการวางโครงสร้างระบบสารสนเทศให้ตอบโจทย์การแก้ปัญหาด้านสิ่งแวดล้อม

1.7.2.3 พัฒนาทักษะการจัดการฐานข้อมูลบนระบบคลาวด์

ผู้พัฒนาจะได้รับประสบการณ์ในการจัดการและจัดเก็บข้อมูลรูปภาพ ข้อมูลผู้ใช้งาน และสถิติการทิ้งขยะอย่างเป็นระบบ ผ่านการใช้เครื่องมือจัดการฐานข้อมูลแบบ NoSQL

## **2.1 บริบทขององค์กร**

ในการวิจัยครั้งนี้ คณะผู้วิจัยได้กำหนดพื้นที่กรณีศึกษาคือ มหาวิทยาลัยราชภัฏเพชรบูรณ์ ซึ่งมีนโยบายขับเคลื่อนสู่การเป็นมหาวิทยาลัยสีเขียว (Green University) ประจำปี พ.ศ. 2566 โดยมุ่งเน้นประเด็นยุทธศาสตร์ด้านการจัดการของเสีย (ข้อ 3.3) ที่สนับสนุนการลดและคัดแยกขยะมูลฝอยตามหลัก 3Rs (Reduce, Reuse, Recycle) ควบคู่ไปกับการส่งเสริมนวัตกรรมเพื่อสร้างวินัย จิตสำนึก และวัฒนธรรมองค์กรด้านการจัดการขยะอย่างยั่งยืนให้กับบุคลากรทุกระดับ

อย่างไรก็ตาม จากการสำรวจบริบทพื้นที่และกระบวนการปฏิบัติงานจริงพบว่า แม้สถาบันจะมีนโยบายที่ชัดเจน แต่ในระดับปฏิบัติการยังคงขาดเครื่องมือดิจิทัลที่ช่วยอำนวยความสะดวกและ \"สร้างแรงจูงใจ\" ในการคัดแยกขยะตั้งแต่ต้นทาง รวมไปถึงขาดการบันทึกจัดเก็บข้อมูลการทิ้งขยะที่เป็นระบบ ส่งผลให้การขับเคลื่อนนโยบายขาดความต่อเนื่อง และผู้ดูแลระบบไม่มีฐานข้อมูลเชิงสถิติที่เพียงพอต่อการนำไปใช้บริหารจัดการด้านสิ่งแวดล้อมได้อย่างมีประสิทธิภาพ

ด้วยเหตุนี้ คณะผู้วิจัยจึงได้นำกรอบความต้องการดังกล่าวมาพัฒนาเว็บแอปพลิเคชัน \"EcoBin Connect\" เพื่อเป็นนวัตกรรมซอฟต์แวร์ที่ตอบสนองต่อนโยบายของมหาวิทยาลัยอย่างเป็นรูปธรรม โดยเว็บแอปพลิเคชันจะทำหน้าที่เป็นเครื่องมือช่วยบันทึกภาพถ่าย รวบรวมสถิติการคัดแยกขยะ และมีระบบมอบแต้มสะสมเพื่อกระตุ้นการมีส่วนร่วม ซึ่งจะช่วยเชื่อมโยงพฤติกรรมการจัดการขยะของบุคลากรเข้ากับระบบบริหารจัดการข้อมูลส่วนกลางได้อย่างยั่งยืน

## **2.2 ทฤษฎีที่เกี่ยวข้อง**

### 2.2.1 ทฤษฎีการจำแนกประเภทพลาสติกเพื่อการรีไซเคิล

อ้างอิงจากประกาศและข้อมูลของกรมการเปลี่ยนแปลงสภาพภูมิอากาศและสิ่งแวดล้อม (DCCE) กระบวนการรีไซเคิลที่จะเกิดประโยชน์ต่อสิ่งแวดล้อมสูงสุดนั้น จำเป็นต้องเริ่มต้นจากการคัดแยกขยะพลาสติกให้ถูกต้องตามประเภทเสียก่อน ทั้งนี้เพื่อเป็นการยกระดับคุณภาพเศษพลาสติกให้มีปริมาณและคุณภาพเพียงพอต่อการนำไปเป็นวัตถุดิบในภาคธุรกิจรีไซเคิล

โดยพลาสติกที่สามารถนำไปรีไซเคิลได้ตามมาตรฐาน จะมีสัญลักษณ์ตัวเลขและตัวอักษรกำกับไว้เพื่อความสะดวกในการคัดแยก แบ่งออกเป็น 7 ประเภทหลัก ได้แก่

2.2.1.1 PETE/PET พอลิเอทิลีนเทเรฟทาเลต เป็นพลาสติกใสแข็ง ทนแรงกระแทกดี นิยมใช้ทำขวดน้ำดื่มและขวดน้ำอัดลม

2.2.1.2 HDPE พอลิเอทิลีนความหนาแน่นสูง เป็นพลาสติกที่เหนียว แตกยาก และยืดได้มาก นิยมใช้ทำขวดนม ขวดแชมพู และขวดน้ำยาล้างจาน

2.2.1.3 PVC พอลิไวนิลคลอไรด์ ใช้ทำท่อน้ำประปา สายยางใส และแผ่นฟิล์มห่ออาหาร

2.2.1.4 LDPE พอลิเอทิลีนความหนาแน่นต่ำ เป็นพลาสติกนิ่ม ยืดตัวได้มาก นิยมใช้ทำถุงหูหิ้ว และถุงขยะ

2.2.1.5 PP พอลิพรอพิลีน เป็นพลาสติกใส ทนต่อความร้อนและสารเคมีได้ดี นิยมใช้ทำภาชนะบรรจุอาหาร ถ้วย และแก้วโยเกิร์ต

2.2.1.6 PS พอลิสไตรีน เป็นพลาสติกใสแต่เปราะและแตกง่าย นิยมใช้ทำโฟมใส่อาหารและช้อนส้อมพลาสติก

2.2.1.7 พลาสติกอื่น ๆ เป็นพลาสติกแข็งชนิดอื่น ๆ ที่สามารถนำมาหลอมใหม่ได้ เช่น เคสโทรศัพท์มือถือ หรือชิ้นส่วนรถยนต์

## **2.5 ภาษาและเครื่องมือที่ใช้ในการพัฒนา**

###  2.5.1 Next.js (React), Tailwind CSS

จีราวุธ วารินทร์ (2564) อธิบายว่า Flutter เป็นชุดเครื่องมือพัฒนาซอฟต์แวร์ (Software Development Kit: SDK) ที่ถูกพัฒนาโดย Google สำหรับสร้างส่วนติดต่อผู้ใช้ (User Interface) และพัฒนาเว็บแอปพลิเคชันแบบข้ามแพลตฟอร์ม (Cross-Platform) จุดเด่นสำคัญของ Flutter คือความสามารถในการเขียนโปรแกรมเพียงชุดเดียว (Single Codebase) แต่สามารถนำเว็บแอปพลิเคชันไปทำงานได้ทั้งบนระบบปฏิบัติการ Android และ iOS ได้พร้อม ๆ กัน ซึ่งช่วยลดระยะเวลา ความซ้ำซ้อน และต้นทุนในการพัฒนาเว็บแอปพลิเคชันได้อย่างมีประสิทธิภาพ

###  2.5.2 ภาษา TypeScript, Golang 

นพรัตน์ บัวพรหมมี (2567) ระบุว่า ภาษา TypeScript, Golang เป็นภาษาโปรแกรมเชิงวัตถุ (Object-Oriented Programming) ที่พัฒนาโดย Google และเป็นภาษาหลักที่ใช้ในการพัฒนาเว็บแอปพลิเคชันร่วมกับ Next.js (React), Tailwind CSS โครงสร้างของภาษา TypeScript, Golang ถูกออกแบบมาให้รองรับการทำงานแบบอซิงโครนัส (Asynchronous) ซึ่งมีความเหมาะสมอย่างยิ่งกับการพัฒนาเว็บแอปพลิเคชันที่ต้องมีการเชื่อมต่อและรับส่งข้อมูลกับเครื่องแม่ข่าย (Server) อย่างต่อเนื่อง ทำให้การประมวลผลและการทำงานของเว็บแอปพลิเคชันมีความลื่นไหล ไม่สะดุด

###  2.5.3 Firebase Authentication และระบบฐานข้อมูล

นพรัตน์ บัวพรหมมี (2567) กล่าวว่า Firebase เป็นแพลตฟอร์มให้บริการระบบหลังบ้าน (Backend as a Service) ของ Google ที่รองรับการทำงานร่วมกับเว็บแอปพลิเคชันได้อย่างมีประสิทธิภาพ โดยในส่วนของ Firebase Authentication เป็นบริการยืนยันตัวตนที่มีมาตรฐานความปลอดภัยระดับสากล รองรับการจัดการสิทธิ์ผู้ใช้งานและการเข้าสู่ระบบผ่านอีเมลและรหัสผ่าน (Email/Password) ได้อย่างสะดวกรวดเร็ว นอกจากนี้ บริการฐานข้อมูลและพื้นที่จัดเก็บไฟล์ของ Firebase (เช่น Cloud Storage และ Firestore) ยังมีความยืดหยุ่นสูง สามารถรองรับการบันทึกและจัดเก็บข้อมูลการจัดการขยะได้อย่างครบถ้วน ไม่ว่าจะเป็น รูปภาพของขยะ ข้อมูลปริมาณ และน้ำหนักขยะ เพื่อให้ระบบสามารถดึงข้อมูลไปประมวลผลหรือแสดงผลแบบเรียลไทม์ต่อไป

###  2.5.4 Android Studio

กิตติพงษ์ สุวรรณราช (2565) กล่าวว่า Android Studio เป็นโปรแกรมสภาพแวดล้อมการทำงานแบบรวม (Integrated Development Environment: IDE) อย่างเป็นทางการจาก Google ที่ออกแบบมาเพื่อการพัฒนาเว็บแอปพลิเคชันบนระบบปฏิบัติการ Android โดยเฉพาะ โปรแกรมนี้มีเครื่องมือที่ครอบคลุมตั้งแต่การเขียนโค้ด การออกแบบส่วนติดต่อผู้ใช้ (UI) ไปจนถึงการทดสอบการทำงานของเว็บแอปพลิเคชันผ่านโปรแกรมจำลอง (Emulator) นอกจากนี้ เมื่อใช้งานร่วมกับ Next.js (React), Tailwind CSS ตัว Android Studio ยังทำหน้าที่เป็นเครื่องมือหลักในการคอมไพล์ (Compile) และแก้ไขข้อผิดพลาด (Debug) ของโปรแกรมได้อย่างมีประสิทธิภาพ

###  2.5.5 สมาร์ตโฟน

ณัฐพล ธนเชวงสกุล (2566) อธิบายว่า สมาร์ตโฟนเป็นอุปกรณ์โทรศัพท์เคลื่อนที่ที่มีระบบปฏิบัติการและมีความสามารถในการประมวลผลเทียบเท่าคอมพิวเตอร์ขนาดย่อม ในกระบวนการพัฒนาเว็บแอปพลิเคชัน สมาร์ตโฟนถูกนำมาใช้เป็นอุปกรณ์ฮาร์ดแวร์สำคัญสำหรับการทดสอบการทำงานของระบบในสภาพแวดล้อมจริง (Real Device Testing) เพื่อตรวจสอบความถูกต้องของการแสดงผล การตอบสนองของหน้าจอสัมผัส (Touchscreen) รวมถึงการทำงานร่วมกับฮาร์ดแวร์เฉพาะทางของตัวเครื่อง เช่น กล้องถ่ายรูปสำหรับการสแกนหรือถ่ายภาพขยะ เพื่อให้แน่ใจว่าเว็บแอปพลิเคชันสามารถทำงานได้อย่างสมบูรณ์ก่อนนำไปใช้งานจริง

## **2.6 ระบบเครือข่าย**

ศุภกิจ อาวิพันธุ์ (2564) อธิบายว่า ระบบเครือข่ายคอมพิวเตอร์คือการเชื่อมต่ออุปกรณ์คอมพิวเตอร์หลายเครื่องเพื่อให้สามารถสื่อสารและแลกเปลี่ยนข้อมูลระหว่างกันได้ โดยในงานวิจัยของเขาได้กล่าวถึงการแบ่งประเภทของเครือข่ายตามอาณาเขตการเชื่อมต่อ ซึ่งประกอบด้วย LAN (Local Area Network) ที่เหมาะกับการเชื่อมต่อภายในพื้นที่เล็ก เช่น บ้าน โรงเรียน หรือสำนักงาน, MAN (Metropolitan Area Network) ซึ่งเป็นการเชื่อมต่อในระดับเมือง และ WAN (Wide Area Network) ที่ครอบคลุมระยะทางไกล เช่น ระหว่างจังหวัดหรือประเทศ เพื่อให้การสื่อสารเป็นไปอย่างรวดเร็วและมีประสิทธิภาพมากขึ้น

ระบบเครือข่าย (Network System) หมายถึงระบบที่เชื่อมต่อระหว่างอุปกรณ์หรือคอมพิวเตอร์หลายๆ เครื่อง เพื่อให้สามารถสื่อสารและแลกเปลี่ยนข้อมูลระหว่างกันได้ อุปกรณ์ในระบบเครือข่ายอาจประกอบไปด้วยคอมพิวเตอร์ เซิร์ฟเวอร์ เราเตอร์ สวิตช์ และอุปกรณ์อื่นๆ ที่สามารถเชื่อมต่อและสื่อสารผ่านกันได้ โดยใช้สื่อกลางต่างๆ เช่น สายเคเบิลหรือสัญญาณไร้สาย ระบบเครือข่ายถูกออกแบบมาเพื่อรองรับการส่งข้อมูลระหว่างอุปกรณ์ต่างๆ ซึ่งอาจอยู่ในรูปแบบของข้อความ (Text) ภาพ (Image) เสียง (Audio) วิดีโอ (Video) หรือข้อมูลไฟล์อื่นๆ มีองค์ประกอบครบทั้ง 5 อันได้แก่

1\) ข่าวสาร (Message) คือข้อมูลหรือสารสนเทศที่ต้องการส่งผ่านระบบเครือข่าย ซึ่งอาจอยู่ในรูปแบบของข้อความ ข้อมูลเสียง ภาพ หรือไฟล์ประเภทต่างๆ ข่าวสารนี้จะถูกเตรียมเพื่อส่งจากผู้ส่งไปยังผู้รับผ่านสื่อกลางที่ใช้ในการสื่อสาร

2\) ผู้ส่ง (Sender) คือแหล่งที่มาของข่าวสารหรือข้อมูล อาจเป็นอุปกรณ์คอมพิวเตอร์ โทรศัพท์มือถือ หรือผู้ใช้งานที่ต้องการส่งข่าวสารไปยังผู้รับ ผู้ส่งจะมีหน้าที่เตรียมข้อมูลและใช้อุปกรณ์หรือซอฟต์แวร์เพื่อส่งข้อมูลผ่านเครือข่าย

3\) ผู้รับ (Receiver) เป็นผู้ที่ปลายทางซึ่งจะได้รับข่าวสารจากผู้ส่ง การทำงานของผู้รับคือการรับข้อมูลที่ส่งมาและแปลงข้อมูลเหล่านั้นให้อยู่ในรูปแบบที่เข้าใจได้ เช่น การแสดงผลข้อความหรือการเล่นไฟล์เสียง

4\) สื่อกลางส่งข้อมูล (Transmission Medium) คือช่องทางที่ใช้ในการถ่ายโอนข้อมูลจากผู้ส่งไปยังผู้รับ ซึ่งสามารถเป็นได้ทั้งสื่อที่เป็นสาย เช่น สายเคเบิลใยแก้วนำแสง สายทองแดง หรือสื่อไร้สาย เช่น สัญญาณวิทยุ คลื่นไมโครเวฟ สัญญาณอินฟราเรด และสัญญาณวิทยุที่ใช้ในเครือข่าย Wi-Fi

5\) โปรโตคอล (Protocol) คือช่องทางที่ใช้ในการถ่ายโอนข้อมูลจากผู้ส่งไปยังผู้รับ ซึ่งสามารถเป็นได้ทั้งสื่อที่เป็นสาย เช่น สายเคเบิลใยแก้วนำแสง สายทองแดง หรือสื่อไร้สาย เช่น สัญญาณวิทยุ คลื่นไมโครเวฟ สัญญาณอินฟราเรด และสัญญาณวิทยุที่ใช้ในเครือข่าย Wi-Fi

###  2.6.1 อินเทอร์เน็ต (Internet)

สุวิมล ราวัง (2554) อธิบายว่า อินเทอร์เน็ตเป็นเครื่องมือที่มีความสำคัญในการอำนวยความสะดวกให้การเข้าถึงข้อมูลและการสื่อสารเป็นไปได้อย่างรวดเร็วและง่ายดาย ซึ่งส่งผลต่อพฤติกรรมและวิถีชีวิตของผู้ใช้งานอย่างมาก โดยเฉพาะในด้านการศึกษาและธุรกิจที่อินเทอร์เน็ตได้กลายมาเป็นสื่อกลางหลักในการสื่อสารและทำธุรกรรมต่าง ๆ

อินเทอร์เน็ต (Internet) คือเครือข่ายคอมพิวเตอร์ขนาดใหญ่ที่เชื่อมโยงเครือข่ายย่อยๆ จากทั่วโลกเข้าด้วยกัน ทำให้ผู้ใช้งานสามารถแลกเปลี่ยนข้อมูล สื่อสาร และเข้าถึงบริการต่างๆ ผ่านคอมพิวเตอร์หรืออุปกรณ์อิเล็กทรอนิกส์อื่นๆ ได้โดยไม่จำกัดสถานที่และเวลา อินเทอร์เน็ตถือเป็นระบบเครือข่ายที่ใหญ่ที่สุดในโลก ซึ่งเชื่อมโยงเครือข่ายประเภทต่างๆ เช่น LAN, WAN, และ MAN เข้าด้วยกันผ่านสื่อกลางทั้งแบบมีสายและไร้สาย เช่น สายไฟเบอร์ออปติก หรือสัญญาณ Wi-Fi

ข้อดีของการใช้สารสนเทศผ่านอินเทอร์เน็ต

1\) การเข้าถึงข้อมูลอย่างรวดเร็ว อินเทอร์เน็ตช่วยให้ผู้ใช้สามารถค้นหาข้อมูล สารสนเทศ และแหล่งความรู้จากทั่วโลกได้ง่ายและรวดเร็ว ไม่ว่าจะเป็นข้อมูลด้านวิทยาศาสตร์, เทคโนโลยี, การศึกษา หรือความบันเทิง

2\) การสื่อสารที่สะดวกและรวดเร็ว อินเทอร์เน็ตทำให้การสื่อสารระหว่างบุคคลเกิดขึ้นได้ทันทีผ่านอีเมล, แชท, โซเชียลมีเดีย, และการประชุมออนไลน์ ทำให้ไม่จำกัดระยะทางระหว่างผู้คนที่ต้องการติดต่อกัน

3\) การทำงานร่วมกันแบบออนไลน์ การทำงานร่วมกันผ่านอินเทอร์เน็ต เช่น การประชุมทางไกล การใช้เอกสารออนไลน์ หรือการทำงานจากระยะไกล ช่วยให้การทำงานเป็นทีมง่ายขึ้น แม้สมาชิกจะอยู่ต่างสถานที่กัน

4\) การช็อปปิ้งและการธนาคารออนไลน์ อินเทอร์เน็ตช่วยให้ผู้ใช้งานสามารถซื้อสินค้าและบริการได้จากที่บ้าน และทำธุรกรรมทางการเงินผ่านอินเทอร์เน็ตอย่างสะดวกปลอดภัย เช่น การชำระเงินออนไลน์ หรือการโอนเงิน

5\) การสร้างเครือข่ายและชุมชนออนไลน์ ผู้ใช้งานสามารถสร้างเครือข่ายทางสังคมและเข้าร่วมชุมชนออนไลน์ที่มีความสนใจเหมือนกันได้ทั่วโลก เช่น ฟอรัม, กลุ่มสนทนา, หรือโซเชียลมีเดีย

6\) การศึกษาผ่านระบบออนไลน์ อินเทอร์เน็ตเป็นเครื่องมือสำคัญที่ช่วยในการศึกษาและการเรียนรู้ด้วยตนเอง ผู้ใช้สามารถเข้าถึงแหล่งข้อมูลการศึกษาออนไลน์ฟรี เช่น หลักสูตร, วิดีโอการสอน, หรือเอกสารวิชาการต่างๆ

ข้อเสียของการใช้สารสนเทศผ่านอินเทอร์เน็ต

1\) การแพร่กระจายของข้อมูลที่ผิดและบิดเบือน อินเทอร์เน็ตทำให้ข้อมูลต่างๆ สามารถเผยแพร่ได้ง่าย แต่บางครั้งข้อมูลเหล่านั้นอาจเป็นข้อมูลที่ผิดหรือไม่ถูกต้อง เช่น ข่าวปลอม, ข้อมูลหลอกลวง, หรือการบิดเบือนความจริง

2\) ปัญหาด้านความปลอดภัยและความเป็นส่วนตัว การใช้บริการออนไลน์อาจเสี่ยงต่อการถูกโจมตีจากผู้ไม่หวังดี เช่น การแฮกข้อมูล, การขโมยข้อมูลส่วนบุคคล, การโจมตีทางไซเบอร์ และไวรัสคอมพิวเตอร์

3\) การเสพติดอินเทอร์เน็ต การใช้เวลาออนไลน์มากเกินไปอาจส่งผลให้ผู้ใช้งานติดอินเทอร์เน็ต ซึ่งสามารถนำไปสู่ปัญหาด้านสุขภาพจิตและสุขภาพกาย เช่น ความเครียด, ภาวะซึมเศร้า, หรือปัญหาการนอนหลับ

4\) การละเมิดลิขสิทธิ์ บนอินเทอร์เน็ตมีการแบ่งปันเนื้อหาที่ผิดกฎหมาย เช่น การดาวน์โหลดเพลง, ภาพยนตร์, หรือซอฟต์แวร์ที่ไม่มีการอนุญาต ซึ่งเป็นการละเมิดลิขสิทธิ์และกฎหมายด้านทรัพย์สินทางปัญญา

5\) ผลกระทบต่อการสื่อสารทางสังคมในชีวิตจริง การใช้โซเชียลมีเดียและการสื่อสารผ่านออนไลน์มากเกินไป อาจทำให้ผู้ใช้งานสูญเสียความสามารถในการสื่อสารและปฏิสัมพันธ์กับคนรอบข้างในชีวิตจริง

## **2.7 การวิเคราะห์และออกแบบระบบ**

### 2.6.1 ความหมายของการวิเคราะห์และออกแบบระบบ

จุฑาวุฒิ จันทรมาลี (2563) ระบุว่า การวิเคราะห์และออกแบบระบบเป็นกระบวนการพัฒนาระบบเทคโนโลยีสารสนเทศที่มีอยู่เดิมหรือระบบปัจจุบันให้ตรงกับความต้องการขององค์กรหรือหน่วยงาน โดยมีขั้นตอนการทำงานที่เป็นระบบและใช้อุปกรณ์ต่าง ๆ ที่เกี่ยวข้องเพื่อให้การวิเคราะห์และการออกแบบระบบเป็นไปอย่างมีประสิทธิภาพ

### 2.6.2 ความหมายของการวิเคราะห์ระบบ 

จันทร์ขาวและดนิตา (2565) อธิบายว่า การวิเคราะห์ระบบ (System Analysis) เป็นกระบวนการศึกษาระบบงานปัจจุบันอย่างละเอียด เพื่อพิจารณาข้อมูล กระบวนการทำงาน ปัญหา และความต้องการของผู้ใช้งาน โดยมีวัตถุประสงค์เพื่อทำความเข้าใจคุณลักษณะของระบบใหม่ที่ควรพัฒนา รวมถึงระบุฟังก์ชันที่จำเป็นต้องปรับปรุงหรือเพิ่มเติมให้ตรงกับความต้องการของผู้ใช้และหน่วยงาน

กระบวนการนี้มีความสำคัญอย่างยิ่งในการกำหนดความต้องการของระบบ (Requirement Analysis) เพราะช่วยให้ข้อมูลที่ใช้สำหรับออกแบบระบบใหม่มีความถูกต้อง ชัดเจน และครบถ้วน ส่งผลให้การออกแบบ การพัฒนา และการนำระบบไปใช้งานจริงเป็นไปอย่างราบรื่นทั้งในด้านประสิทธิภาพและความเหมาะสมต่อองค์กร

2.6.2.1 การกำหนดความต้องการของระบบ

การกำหนดความต้องการของระบบเป็นขั้นตอนที่สำคัญในการเริ่มต้นวิเคราะห์ระบบ โดยผู้วิเคราะห์จะทำการสำรวจและรวบรวมข้อมูลจากผู้ใช้งานและผู้มีส่วนเกี่ยวข้อง เพื่อระบุว่าระบบต้องมีคุณสมบัติอะไรบ้าง และต้องตอบสนองต่อความต้องการใดในองค์กร ขั้นตอนนี้เป็นจุดเริ่มต้นของการพัฒนาระบบใหม่ที่มีประสิทธิภาพ โดยมุ่งเน้นที่การระบุปัญหาและความต้องการ

2.6.2.2 การวิเคราะห์ความต้องการระบบใหม่

การวิเคราะห์ความต้องการระบบใหม่ ซึ่งเป็นกระบวนการที่ทำการวิเคราะห์อย่างละเอียดถึงความเป็นไปได้ของการพัฒนาระบบ การประเมินทางเลือกต่างๆ และกำหนดความสามารถที่ระบบใหม่จะต้องมี เพื่อให้สามารถตอบสนองต่อความต้องการของผู้ใช้งานและองค์กรได้อย่างเต็มที่

### 2.6.3 การออกแบบระบบ

จุฑาวุฒิ จันทร์ธรรมมาลี (2563) ระบุว่า การวิเคราะห์และออกแบบระบบ (System Analysis and Design) เป็นกระบวนการพัฒนาระบบเทคโนโลยีสารสนเทศโดยการปรับปรุงจากระบบเดิมหรือระบบปัจจุบันให้ตรงกับความต้องการขององค์กรหรือหน่วยงาน กระบวนการนี้เป็นการทำงานที่มีขั้นตอนอย่างชัดเจน และใช้เครื่องมือที่เกี่ยวข้องเพื่อช่วยในการวิเคราะห์และออกแบบระบบ เพื่อให้ได้ระบบที่มีประสิทธิภาพและสามารถตอบสนองความต้องการได้อย่างเต็มที่ตามวัตถุประสงค์ที่ตั้งไว้

การออกแบบเป็นการกำหนดรายละเอียดของระบบใหม่ เช่น การออกแบบฐานข้อมูล การสร้างโครงสร้างของระบบ และการกำหนดวิธีการทำงานของส่วนต่างๆ ของระบบ

### 2.6.4 วงจรพัฒนาระบบ

ศรีนวล ฟองมณี (2560) ระบุว่า วงจรการพัฒนาระบบ (System Development Life Cycle: SDLC) เป็นกระบวนการที่ใช้ในการพัฒนาระบบสารสนเทศ ซึ่งประกอบด้วยขั้นตอนที่ชัดเจนและเรียงลำดับอย่างเป็นระบบ เพื่อให้การพัฒนาระบบสามารถตอบสนองความต้องการของผู้ใช้งานได้อย่างมีประสิทธิภาพ กระบวนการนี้รวมถึงการวางแผน การออกแบบ การดำเนินการ และการดูแลรักษาระบบ เพื่อให้การพัฒนาสามารถบรรลุเป้าหมายขององค์กรได้อย่างดีที่สุด

วงจรการพัฒนาระบบ (System Development Life Cycle : SDLC) คือ การแบ่งขั้นตอนกระบวนการพัฒนาระบบงาน หรือระบบเทคโนโลยีสารสนเทศด้วย เพื่อช่วยแก้ปัญหาทางธุรกิจหรือตอบสนองความต้องการขององค์กรโดยระบบที่จะพัฒนานั้นอาจเป็นการพัฒนาระบบใหม่หรือการปรับปรุงระบบเดิมให้ดีขึ้นก็ได้ การพัฒนาระบบแบ่งออกเป็น 7 ขั้นตอน ดังนี้

2.6.4.1 การค้นหาปัญหาขององค์กร (Problem Recognition)

เป็นการกำหนดเป้าหมายที่ชัดเจนในการปรับปรุงโดยใช้ระบบเข้ามาช่วยนำข้อมูลปัญหาที่ได้มาจำแนกจัดกลุ่มและจัดลำดับความสำคัญ เพื่อใช้คัดเลือกโครงการที่เหมาะสมที่สุดมาพัฒนา โดยโครงการที่จะทำการพัฒนาต้องสามารถแก้ปัญหาที่มีในองค์กรและให้ประโยชน์กับองค์กร

2.6.4.2 การศึกษาความเหมาะสม (Feasibility Study)

การศึกษาว่าเหมาะสมหรือไม่ที่จะปรับเปลี่ยนระบบ โดยให้เสียค่าใช้จ่าย (Cost) และเวลา (Time) น้อยที่สุดแต่ให้ได้ผลลัพธ์ที่น่าพอใจ และหาความต้องการของผู้เกี่ยวข้องใน 3 เรื่อง คือ เทคนิคเครื่องมือหรืออุปกรณ์ที่ใช้ บุคลากรและความพร้อม และความคุ้มค่า เพื่อใช้นำเสนอต่อผู้บริหารพิจารณาอนุมัติดำเนินการต่อไป

2.6.4.3 การวิเคราะห์ (Analysis)

เป็นการรวบรวมข้อมูลปัญหาความต้องการที่มีเพื่อนำไปออกแบบระบบ ขั้นตอนนี้จะศึกษาจากผู้ใช้ โดยวิเคราะห์การทำงานของระบบเดิม (As Is) และความต้องการที่มีจากระบบใหม่ (To Be) จากนั้นนำผลการศึกษาและวิเคราะห์มาเขียนเป็นแผนภาพผังงานระบบ (System Flowchart) และทิศทางการไหลของข้อมูล (Data Flow Diagram)

2.6.4.4 การออกแบบ (Design)

นำผลการวิเคราะห์มาออกแบบเป็นแนวคิด (Logical Design) เพื่อแก้ไขปัญหา โดยในส่วนนี้จะยังไม่ได้มีการระบุถึงรายละเอียดและคุณลักษณะอุปกรณ์มากนัก เน้นการออกแบบโครงร่างบนกระดาษ แล้วส่งให้ผู้ออกแบบระบบนำไปออกแบบ (System Design) ซึ่งขั้นตอนนี้จะเริ่มมีการระบุลักษณะการทำงานของระบบทางเทคนิค รายละเอียดคุณลักษณะอุปกรณ์ที่ใช้ เทคโนโลยีที่ใช้ ชนิดฐานข้อมูลการออกแบบ เครือข่ายที่เหมาะสม ลักษณะของการนำข้อมูลเข้า ลักษณะรูปแบบรายงานที่เกิด และผลลัพธ์ที่ได้

2.6.4.5 การพัฒนาและทดสอบ (Development & Test)

เป็นขั้นตอนการการเขียนโปรแกรม (Coding) เพื่อพัฒนาระบบจากแบบบนกระดาษให้เป็นระบบตามคุณลักษณะที่กำหนดไว้ จากนั้นทำการทดสอบหาข้อผิดพลาด (Testing) เพื่อตรวจสอบความถูกต้อง จนมั่นใจว่าถูกต้องและตรงตามความต้องการ หากพบว่ามีข้อผิดพลาดเกิดขึ้นจากการทำงานของระบบต้องปรับแก้ไขให้เรียบร้อยพร้อมใช้งานก่อนนำไปติดตั้งใช้จริง

2.6.4.6 การติดตั้ง (Implementation)

เป็นขั้นตอนการนำระบบที่พัฒนาจนสมบูรณ์มาติดตั้ง (Installation) และเริ่มใช้งานจริง ในส่วนนี้นอกจากติดตั้งระบบใช้งานแล้ว ยังต้องมีการจัดเตรียมขั้นตอนการสนับสนุนส่งเสริมการใช้งานให้สามารถใช้งานได้อย่างสมบูรณ์ โดยจัดทำหลักสูตรฝึกอบรมผู้ใช้งาน (Training) เอกสารประกอบระบบ (Documentation) และแผนการบริการให้ความช่วยเหลือ (Support) เพื่อให้ระบบสามารถใช้งานได้อย่างต่อเนื่อง

2.6.4.7 การซ่อมบำรุงระบบ (System Maintenance

เป็นขั้นตอนการบำรุงรักษาระบบต่อเนื่องหลังจากเริ่มดำเนินการ ผู้ใช้ระบบอาจจะพบกับปัญหาที่เกิดขึ้นภายหลัง เช่น ปัญหาเนื่องจากความไม่คุ้นเคยกับระบบใหม่ จึงควรกำหนดแผนค้นหาปัญหาอย่างต่อเนื่อง ติดตามประเมินผล เก็บรวบรวมคำร้องขอให้ปรับปรุงระบบ วิเคราะห์ข้อมูลร้องขอให้ปรับปรุงระบบ จากนั้นออกแบบการทำงานที่ต้องการปรับปรุงแก้ไขและติดตั้ง ซึ่งต้องมีการฝึกอบรมการใช้งานระบบให้แก่ผู้ใช้งาน เพื่อที่จะทราบความพึงพอใจของผู้ใช้

###  2.6.5 แบบจำลองความสัมพันธ์ระหว่างข้อมูล

สมชาย สุวรรณา (2562) ได้กล่าวว่า แบบจำลองความสัมพันธ์ระหว่างข้อมูล (Relational Data Model) ถูกกำหนดโดย Dr. E.F. Codd ซึ่งประกอบด้วยโครงสร้างที่เป็นลักษณะของตารางสองมิติ ประกอบด้วยแถวและคอลัมน์ โดยแต่ละตารางจะเรียกว่า \"รีเลชัน\" (Relation) ซึ่งมีคุณสมบัติที่สำคัญ เช่น ไม่มีข้อมูลที่ซ้ำกัน (No duplicate tuples) และค่าของข้อมูลแต่ละแอตทริบิวต์จะเป็นค่าเดี่ยวๆ (Atomic) เท่านั้น

เกี่ยวข้องกับการวิเคราะห์ความสัมพันธ์ระหว่างข้อมูลและกระบวนการต่าง ๆ เพื่อให้เห็นภาพรวมการทำงานของระบบ หนึ่งในเครื่องมือที่ใช้ในการออกแบบระบบคือ Data Flow Diagram (DFD) ซึ่งช่วยให้เห็นการไหลของข้อมูลและกระบวนการต่าง ๆ ที่เกิดขึ้นภายในระบบ การออกแบบโดยใช้ DFD ช่วยให้เข้าใจการทำงานของระบบได้ชัดเจน และสามารถวางแผนการพัฒนาระบบได้ง่ายขึ้น โดยสัญลักษณ์ที่ใช้ในการเขียนแผนภาพ Data flow diagram มีดังตารางที่ 2.6

2.6.5.1 การออกแบบระบบโดยใช้ Data flow diagram

สมชาย อินทรประสิทธิ์ (2563) ระบุว่า การออกแบบระบบโดยใช้แผนภาพกระแสข้อมูล (Data Flow Diagram: DFD) เป็นวิธีการที่ใช้เพื่อแสดงการไหลของข้อมูลภายในระบบ ทำให้เข้าใจการทำงานและความสัมพันธ์ระหว่างกระบวนการต่าง ๆ ได้ดีขึ้น ใน DFD มีการใช้สัญลักษณ์หลัก ได้แก่ Process, Data Store, Data Flow และ External Entity ซึ่งช่วยอธิบายการไหลของข้อมูลและการเชื่อมโยงระหว่างองค์ประกอบต่าง ๆ ของระบบ

Data Flow Diagram (DFD) เป็นเครื่องมือที่ใช้ในการออกแบบระบบที่ช่วยแสดงให้เห็นการเคลื่อนที่ของข้อมูล (Data) ระหว่างกระบวนการต่าง ๆ ในระบบ ซึ่งจะช่วยให้ผู้พัฒนาสามารถเข้าใจโครงสร้างและการทำงานของระบบอย่างละเอียดและชัดเจนขึ้น การออกแบบ DFD มีหลายระดับ ได้แก่ ระดับ Context Diagram (ระดับที่สูงสุด หรือ Level-0) ที่แสดงเพียงการไหลของข้อมูลโดยรวม และ ระดับย่อย (Level-1, Level-2) ที่แสดงรายละเอียดของการไหลข้อมูลแต่ละส่วน

2.6.5.2 แผนภาพบริบท (Context Diagram / Level-0 Diagram)

สมชาย วงษ์สุวรรณ (2561) อธิบายว่า แผนภาพบริบท (Context Diagram หรือ Level-0 Diagram) เป็นแผนภาพที่ใช้แสดงภาพรวมของระบบ โดยแสดงถึงความสัมพันธ์ระหว่างระบบกับสิ่งแวดล้อมภายนอก ซึ่งแสดงข้อมูลเข้าและข้อมูลออกที่เชื่อมโยงกับผู้ใช้งานหรือหน่วยงานต่าง ๆ การใช้แผนภาพบริบทช่วยให้เข้าใจการทำงานทั้งหมดของระบบและเห็นภาพรวมได้อย่างง่ายดาย

Context Diagram หรือ Level-0 Diagram เป็นแผนภาพที่แสดงการไหลของข้อมูลภายในระบบในระดับที่ง่ายที่สุด แผนภาพบริบทนี้จะเน้นไปที่ภาพรวมของระบบทั้งหมด แสดงเพียงกระบวนการหลักหนึ่งกระบวนการ (มักจะเป็นตัวแทนของระบบทั้งหมด) โดยมีการแสดงผู้ใช้งานภายนอก (External Entities) และข้อมูลที่เข้าและออกจากระบบ กระบวนการภายในจะถูกแสดงเป็นภาพเดียวที่แสดงถึงทั้งระบบ โดยไม่ลงลึกถึงรายละเอียดในกระบวนการย่อยภายใน

## **2.8 เอกสารหรืองานวิจัยที่เกี่ยวข้อง**

2.7.1 อนุวัฒน์ พิทักษ์ธรรม (2565) อธิบายว่า ระบบจัดการสิทธิ์การเข้าถึงงานวิจัย (Research Access Control System) คือกระบวนการที่ใช้ในการกำหนดสิทธิ์การเข้าถึงข้อมูลงานวิจัย เพื่อให้มั่นใจว่าผู้ที่มีสิทธิ์เท่านั้นที่จะสามารถเข้าถึงข้อมูลที่สำคัญหรือละเอียดอ่อนได้ ระบบนี้ช่วยป้องกันการเข้าถึงโดยไม่ได้รับอนุญาตและเสริมสร้างความปลอดภัยให้กับข้อมูลงานวิจัย

2.7.2 สมชาย เพ็ญสุข (2563) อธิบายว่า ระบบค้นหางานวิจัย (Research Retrieval System) เป็นเครื่องมือที่ช่วยให้นักวิจัยสามารถค้นหางานวิจัยที่เกี่ยวข้องได้อย่างรวดเร็ว โดยอาศัยเทคโนโลยีในการจัดทำดัชนีและการใช้คำสำคัญ เพื่อให้การค้นหามีประสิทธิภาพและสอดคล้องกับความต้องการของผู้ใช้งานมากที่สุด

2.7.3 ประภัสสร ชัยวัฒน์ (2562) ระบุว่า ระบบเก็บงานวิจัย (Research Storage System) เป็นวิธีการในการจัดการและรวบรวมงานวิจัยให้อยู่ในที่เก็บข้อมูลส่วนกลาง ซึ่งสามารถเป็นฐานข้อมูลออนไลน์หรือระบบจัดเก็บไฟล์ดิจิทัล เพื่อเพิ่มความสะดวกในการเข้าถึงและช่วยป้องกันการสูญหายของข้อมูล

2.7.4 วรรณิภา สุขุมวัฒน์ (2564) ระบุว่า ระบบสอบงานวิจัย (Research Evaluation System) เป็นกระบวนการตรวจสอบและประเมินคุณภาพของงานวิจัย โดยมีวัตถุประสงค์เพื่อให้แน่ใจว่างานวิจัยมีความน่าเชื่อถือ มีการดำเนินการตามหลักเกณฑ์ที่ถูกต้อง และสามารถนำไปประยุกต์ใช้ได้จริง

2.7.5 ศิรินภา แสงแก้ว (2566) ระบุว่า ระบบวิเคราะห์และรายงานผลงานวิจัย (Research Analysis and Reporting System) เป็นระบบที่ช่วยในการประมวลผลข้อมูลจากงานวิจัย และสร้างรายงานในรูปแบบที่ใช้งานง่าย เพื่อให้นักวิจัยสามารถเข้าใจผลลัพธ์และสรุปข้อมูลได้อย่างมีประสิทธิภาพ

2.7.6 จีราวุธ วารินทร์ (2564) อธิบายว่า Flutter เป็นชุดเครื่องมือพัฒนาซอฟต์แวร์ (SDK) จาก Google สำหรับสร้างเว็บแอปพลิเคชันข้ามแพลตฟอร์ม (Cross-Platform) มีจุดเด่นคือการเขียนชุดคำสั่งเพียงชุดเดียว (Single Codebase) แต่สามารถนำไปใช้งานได้ทั้งบนระบบ Android และ iOS โดยอาศัยโครงสร้างแบบวิดเจ็ต (Widget-based) ที่ช่วยให้การออกแบบส่วนติดต่อผู้ใช้ (UI) ทำได้รวดเร็ว ซึ่งช่วยลดระยะเวลาและความซ้ำซ้อนในการพัฒนาได้อย่างมาก

2.7.7 จีราวุธ วารินทร์ (2564) ระบุว่า ภาษา TypeScript, Golang เป็นภาษาโปรแกรมเชิงวัตถุจาก Google ที่ใช้เป็นภาษาหลักในการทำงานร่วมกับ Flutter โครงสร้างภาษารองรับการทำงานแบบอซิงโครนัส (Asynchronous) ทำให้สามารถจัดการประมวลผลที่ใช้เวลานาน เช่น การจำแนกประเภทขยะพลาสติกด้วย AI หรือการรับส่งข้อมูลขนาดใหญ่บนคลาวด์ ได้อย่างราบรื่นโดยไม่ทำให้การแสดงผลของระบบหยุดชะงัก

2.7.8 นพรัตน์ บัวพรหมมี (2567) อธิบายว่า Firebase เป็นระบบจัดการหลังบ้าน (Backend as a Service) จาก Google ที่มีบริการ Firebase Authentication สำหรับตรวจสอบและยืนยันตัวตนผู้ใช้ผ่านอีเมลและรหัสผ่านอย่างปลอดภัย นอกจากนี้ยังมีระบบฐานข้อมูลที่สามารถจัดเก็บข้อมูลที่ซับซ้อน เช่น ภาพถ่ายขยะ ปริมาณ น้ำหนัก และผลประเมินการลดก๊าซเรือนกระจก (Greenhouse Gas Emissions) เพื่อนำมาประมวลผลและแสดงผลแบบทันที (Real-time)

2.7.9 กิตติพงษ์ สุวรรณราช (2565) กล่าวว่า Android Studio เป็นโปรแกรมสภาพแวดล้อมการพัฒนา (IDE) อย่างเป็นทางการสำหรับเว็บแอปพลิเคชันบนระบบ Android โดยรวบรวมเครื่องมือที่จำเป็นไว้อย่างครบถ้วน เช่น เครื่องมือแก้ไขโค้ดและระบบตรวจสอบจุดบกพร่อง รวมถึงมีโปรแกรมจำลอง (Emulator) ที่ช่วยให้นักพัฒนาสามารถทดสอบการทำงานของเว็บแอปพลิเคชันบนคอมพิวเตอร์ได้ก่อนนำไปใช้จริง

2.7.10 ณัฐพล ธนเชวงสกุล (2566) อธิบายว่า สมาร์ตโฟนเป็นอุปกรณ์ฮาร์ดแวร์ที่จำเป็นสำหรับการทดสอบเว็บแอปพลิเคชันในสภาพแวดล้อมจริง (Real Device Testing) เพื่อตรวจสอบประสิทธิภาพการทำงานที่ต้องพึ่งพาอุปกรณ์ภายในเครื่องโดยตรง เช่น การใช้กล้องถ่ายรูปเพื่อสแกนและคัดแยกวัสดุรีไซเคิล หรือการตอบสนองของหน้าจอสัมผัส เพื่อยืนยันว่าเว็บแอปพลิเคชันสามารถทำงานได้อย่างถูกต้องและมีเสถียรภาพ

2.7.11 พิมลพรรณ สมบูรณ์ (2568) อธิบายว่า การจำแนกประเภทพลาสติกเพื่อการรีไซเคิลตามสัญลักษณ์ 1-7 เป็นพื้นฐานสำคัญของกระบวนการรีไซเคิลที่มีประสิทธิภาพ โดย PET (1) ใช้สำหรับขวดน้ำใสแข็งทนกระแทก HDPE (2) เหนียวสำหรับขวดนมหรือแชมพู PVC (3) สำหรับท่อน้ำ LDPE (4) นิ่มสำหรับถุงหูหิ้ว PP (5) ทนความร้อนสำหรับภาชนะอาหาร PS (6) เปราะสำหรับโฟม และอื่นๆ (7) สำหรับพลาสติกผสม.

2.7.12 ธัญญลักษณ์ ใจหาญ (2567) ระบุว่า สถานการณ์ขยะพลาสติกในสถาบันอุดมศึกษามีสัดส่วนสูง เช่น ที่มหาวิทยาลัยพะเยาเฉลี่ย 1,468 กิโลกรัมต่อวัน คิดเป็น 49.54% ของขยะทั้งหมด ซึ่งสูงกว่าค่าเฉลี่ยประเทศ (17.6%) ถึง 2.8 เท่า สะท้อนปัญหาการกำจัดไม่ถูกวิธีและขาดแรงจูงใจ แม้มีแผน Roadmap พ.ศ. 2561-2573.

## 3.1 ศึกษาปัญหาและความต้องการ (Analysis & Requirement) 

ปัจจุบันการจัดการข้อมูลขยะมูลฝอยภายในชุมชนและองค์กรยังขาดความเป็นระบบ ทำให้เกิดปัญหาหลายประการ เช่น การจัดเก็บข้อมูลและสถิติการทิ้งขยะยังคงอยู่ในรูปแบบดั้งเดิมที่ขาดการจัดระเบียบที่ดี ทำให้การเข้าถึงและตรวจสอบฐานข้อมูลปริมาณขยะทำได้ไม่สะดวก ยุ่งยากต่อการนำข้อมูลไปวิเคราะห์ และเสี่ยงต่อการสูญหายของข้อมูล นอกจากนี้ การส่งเสริมพฤติกรรมการคัดแยกขยะยังขาดกลไกการสร้างแรงจูงใจที่เป็นรูปธรรม การตรวจสอบและติดตามพฤติกรรมการคัดแยกขยะของคนในชุมชนยังทำได้ยาก ทำให้การขับเคลื่อนนโยบายด้านสิ่งแวดล้อมเกิดความล่าช้าและไม่ต่อเนื่อง

ด้วยเหตุนี้ จึงมีความต้องการในการพัฒนาระบบเว็บแอปพลิเคชันที่สามารถจัดเก็บข้อมูลการคัดแยกขยะประเภทขวดพลาสติกได้อย่างเป็นระบบ มีประสิทธิภาพในการบันทึกและเข้าถึงข้อมูล โดยเฉพาะการมีระบบอัปโหลดภาพถ่ายและสะสมแต้มผ่านระบบออนไลน์ ที่จะช่วยสร้างแรงจูงใจและทำให้ผู้ใช้งานสามารถติดตามสถิติการคัดแยกขยะของตนเองได้สะดวกมากขึ้น นอกจากนี้ ระบบยังควรสามารถใช้งานผ่านเครือข่ายอินเทอร์เน็ตบนสมาร์ตโฟนได้ทุกที่ทุกเวลา และเสริมสร้างประสิทธิภาพในการบริหารจัดการข้อมูลสำหรับผู้ดูแลระบบ โดยการสรุปรายงานสถิติปริมาณขยะและการตรวจสอบข้อมูลหลักฐานการทิ้งขยะสามารถทำผ่านระบบได้อย่างรวดเร็วและมีประสิทธิภาพ**\**

## 3.2 การวิเคราะห์ระบบ (System Analysis)

จากการรวบรวมข้อมูลในขั้นตอนการศึกษาปัญหาและความต้องการของระบบและนำข้อมูลดังกล่าวมาทำการวิเคราะห์ระบบ เพื่อสร้างแบบจำลองข้อมูลและขั้นตอนการทำงาน

###  3.2.1 คอนเท็กซ์ไดอะแกรม (Context Diagram)

![](media/image6.png){width="5.70625in" height="3.6533398950131235in"}

**รูปที่ 3.1** Context Diagram ระบบเว็บแอปพลิเคชันคัดแยกขยะ

จากรูปที่ 3.1 แสดงแผนภาพบริบท (Context Diagram) ของการออกแบบและพัฒนาระบบเว็บแอปพลิเคชันคัดแยกขยะ ซึ่งประกอบด้วยกลุ่มผู้ใช้งานที่เกี่ยวข้องจำนวน 3 กลุ่ม ดังนี้

3.2.1.1 ผู้ใช้งานแบบไม่ลงทะเบียน ข้อมูลที่นำเข้าสู่ระบบ ได้แก่ คำร้องขอเข้าดูข้อมูลเว็บแอปพลิเคชันเบื้องต้น และข้อมูลภาพถ่ายขยะประเภทขวดพลาสติก (โดยข้อมูลส่วนนี้จะถูกประมวลผลและจัดเก็บเพียงในอุปกรณ์ของผู้ใช้เท่านั้น ไม่ส่งขึ้นฐานข้อมูลหลัก) ข้อมูลที่ได้รับจากระบบ ได้แก่ ข้อมูลแจ้งเตือนผลการตรวจสอบภาพถ่ายขยะ และข้อมูลรายการแคตตาล็อกของรางวัล

3.2.1.2 สมาชิกทั่วไป ข้อมูลที่นำเข้าสู่ระบบ ได้แก่ ข้อมูลการสมัครสมาชิกและเข้าสู่ระบบ ข้อมูลภาพถ่ายขยะประเภทขวดพลาสติกเพื่อบันทึกสถิติ และข้อมูลคำขอทดสอบการแลกของรางวัล ข้อมูลที่ได้รับจากระบบ ได้แก่ ข้อมูลแจ้งเตือนผลการตรวจสอบภาพถ่ายขยะ ข้อมูลแต้มสะสม ข้อมูลกระดานสถิติประวัติการทิ้งขยะส่วนบุคคล และข้อมูลรายการของรางวัล

3.2.1.3 ผู้ดูแลระบบ (Admin) ข้อมูลที่นำเข้าสู่ระบบ ได้แก่ ข้อมูลการเข้าสู่ระบบ ข้อมูลจัดการบัญชีผู้ใช้งาน ข้อมูลการตรวจสอบและยืนยันภาพถ่ายขยะ และข้อมูลจัดการรายการของรางวัล (เพิ่ม/ลบ/แก้ไข) ข้อมูลที่ได้รับจากระบบ ได้แก่ รายงานสถิติปริมาณขยะขวดพลาสติกภาพรวม รายงานสถิติการสะสมแต้มของระบบ และรายงานข้อมูลผู้ใช้งานพร้อมสถานะการทดสอบแลกของรางวัล

###  3.2.2 แผนภาพการไหลของข้อมูล (DFD: Data Flow Diagram Level 0) ![](media/image7.png){width="5.554173228346457in" height="5.84623687664042in"}

**รูปที่ 3.2** DataFlow Diagram Level 0 ของระบบเว็บแอปพลิเคชันคัดแยกขยะ

จากรูปที่ 3.2 แผนภาพการไหลของข้อมูล (Data Flow Diagram Level 0) ของระบบเว็บแอปพลิเคชันคัดแยกขยะ (EcoBin Connect) ประกอบด้วย 4 กระบวนการหลัก ดังนี้

3.2.2.1 กระบวนการที่ 1.0 จัดการข้อมูลสมาชิกและการเข้าสู่ระบบ โดยสมาชิกทั่วไปจะนำเข้าข้อมูลการสมัครสมาชิกและข้อมูลการเข้าสู่ระบบ และผู้ดูแลระบบจะนำเข้าข้อมูลการจัดการบัญชีผู้ใช้งาน ระบบจะจัดเก็บและอัปเดตข้อมูลดังกล่าวไว้ในแหล่งเก็บข้อมูล D1 ข้อมูลผู้ใช้งาน พร้อมส่งผลการเข้าสู่ระบบหรือข้อมูลโปรไฟล์กลับไปยังผู้ใช้งาน

3.2.2.2 กระบวนการที่ 2.0 รับภาพถ่าย วิเคราะห์ด้วย AI และรอการตรวจสอบ โดยสมาชิกทั่วไปและผู้ใช้งานแบบไม่ลงทะเบียน (Guest) จะนำเข้าข้อมูลภาพถ่ายขวดพลาสติก เพื่อให้ระบบวิเคราะห์ด้วย AI เบื้องต้น ส่วนผู้ดูแลระบบจะนำเข้าผลการตรวจสอบและยืนยันความถูกต้องของภาพถ่าย โดยประวัติการทิ้งขยะของสมาชิกทั่วไปจะถูกจัดเก็บใน D2 ข้อมูลประวัติการทิ้งขยะ ในสถานะรอการตรวจสอบ ขณะที่ผลการสแกนทดลองของ Guest จะถูกจัดเก็บใน D4 บันทึกสแกน Guest (guest_logs) ซึ่งไม่ได้แต้มจริง และเมื่อผู้ดูแลระบบอนุมัติแล้ว ระบบจึงบันทึกธุรกรรมแต้มที่เกี่ยวข้องลงใน D3

3.2.2.3 กระบวนการที่ 3.0 จัดการแต้มสะสม ของรางวัล และการแลก โดยผู้ดูแลระบบจะนำเข้าข้อมูลการจัดการรายการของรางวัล (เพิ่ม ลบ แก้ไข) รวมถึงการสแกน QR เพื่อยืนยันการรับของหรือยกเลิกการแลก และสมาชิกทั่วไปจะนำเข้าคำขอแลกของรางวัล โดยรายการของรางวัล การแลก และธุรกรรมแต้มจะถูกจัดเก็บใน D3 ข้อมูลแต้ม ของรางวัล และการแลก ส่วนยอดแต้มสะสมของสมาชิกที่เปลี่ยนแปลงจะถูกอัปเดตใน D1 ข้อมูลผู้ใช้งาน

3.2.2.4 กระบวนการที่ 4.0 ประมวลผลสถิติและรายงาน โดยสมาชิกทั่วไปและผู้ดูแลระบบจะส่งคำร้องขอดูสถิติการคัดแยกขยะ ระบบจะดึงข้อมูลจาก D1 ข้อมูลผู้ใช้งาน, D2 ข้อมูลประวัติการทิ้งขยะ และ D3 ข้อมูลแต้ม ของรางวัล และการแลก เพื่อประมวลผลเป็นกระดานสถิติส่วนบุคคลสำหรับสมาชิก และรายงานภาพรวมปริมาณขยะสำหรับผู้ดูแลระบบ นอกจากนี้ผู้ดูแลระบบยังสามารถจัดการข้อมูลถังขยะ ประเภท

###  3.2.3 การออกแบบแผนภาพกระแสข้อมูล (Data flow Diagram level 1 of Process 1.0)

![](media/image8.png){width="4.001875546806649in" height="3.5902777777777777in"}

**รูปที่ 3.3** Data Flow Diagram Level 1 Process 1.0 จัดการข้อมูลพื้นฐาน

จากรูปที่ 3.3 แผนภาพกระแสข้อมูลระดับ 1 (Data Flow Diagram Level 1) ของกระบวนการที่ 1.0 จัดการข้อมูลสมาชิกและการเข้าสู่ระบบ สามารถอธิบายได้ว่ามีกระบวนการย่อยทั้งหมด 3 กระบวนการ ได้แก่

3.2.3.1 กระบวนการที่ 1.1 สมัครสมาชิก (Register) โดยสมาชิกทั่วไปจะนำเข้าข้อมูลการสมัครสมาชิก เช่น ชื่อ--นามสกุล รหัสนักศึกษา อีเมล และรหัสผ่าน หรือสมัครผ่าน Google Sign-In จากนั้นระบบจะประมวลผลและจัดเก็บข้อมูลผู้ใช้งานใหม่ไว้ในแหล่งเก็บข้อมูล D1 ข้อมูลผู้ใช้งาน พร้อมส่งสถานะการสมัครสำเร็จหรือข้อผิดพลาดกลับไปยังสมาชิก

3.2.3.2 กระบวนการที่ 1.2 เข้าสู่ระบบ (Login) โดยสมาชิกทั่วไปและผู้ดูแลระบบจะนำเข้าข้อมูลเข้าสู่ระบบ เช่น อีเมล เบอร์โทรศัพท์ หรือ Google Sign-In พร้อมรหัสผ่าน (กรณีเข้าสู่ระบบด้วยบัญชีปกติ) จากนั้นระบบจะดึงข้อมูลจาก D1 ข้อมูลผู้ใช้งาน มาเปรียบเทียบและตรวจสอบความถูกต้อง ก่อนส่งสถานะการเข้าสู่ระบบหรือเซสชันกลับไปยังผู้ใช้งาน

3.2.3.3 กระบวนการที่ 1.3 จัดการผู้ใช้งานและโปรไฟล์ (Manage Users) โดยผู้ดูแลระบบจะนำเข้าคำสั่งจัดการบัญชี เช่น การกำหนดบทบาท การให้แต้มโบนัส หรือการปิดบัญชี และสมาชิกทั่วไปสามารถนำเข้าข้อมูลแก้ไขโปรไฟล์ของตนเองได้ จากนั้นระบบจะดึงข้อมูลจาก D1 เพื่อแสดงรายชื่อผู้ใช้หรือโปรไฟล์ และอัปเดตข้อมูลกลับไปยัง D1 หากมีการให้แต้มโบนัส ระบบจะบันทึกธุรกรรมแต้มลงใน D3 ธุรกรรมแต้ม ด้วย

###  3.2.4 การออกแบบแผนภาพกระแสข้อมูล (Data flow Diagram level 1 of Process 2.0)

![](media/image9.png){width="3.9227701224846894in" height="3.4583333333333335in"}

**รูปที่ 3.4** Data Flow Diagram Level 1 Process 2.0 ตรวจสอบภาพถ่ายขยะ

จากรูปที่ 3.4 แผนภาพกระแสข้อมูลระดับ 1 (Data Flow Diagram Level 1) ของกระบวนการที่ 2.0 รับภาพถ่าย วิเคราะห์ด้วย AI และรอการตรวจสอบ สามารถแตกเป็นกระบวนการย่อยได้ 3 กระบวนการ ได้แก่

3.2.4.1 กระบวนการที่ 2.1 รับภาพและวิเคราะห์ด้วย AI (สมาชิก) สมาชิกทั่วไป นำเข้า ข้อมูลภาพถ่ายขวดพลาสติก เข้าสู่ระบบ ระบบจะ ดึงประเภทขวด / แต้มประมาณการ จากแหล่งเก็บข้อมูล D5 ประเภทขวด / กฎคะแนน เพื่อวิเคราะห์ด้วย AI จากนั้น บันทึกรายการขยะ (สถานะ: รอการตรวจสอบ) ลงใน D2 ประวัติการทิ้งขยะ และส่ง ผลวิเคราะห์เบื้องต้น / สถานะรอตรวจสอบ กลับไปยังสมาชิกทั่วไป

3.2.4.2 กระบวนการที่ 2.2 สแกนทดลอง (Guest) ผู้ใช้งานแบบไม่ลงทะเบียน (Guest) นำเข้า ภาพถ่ายสแกนทดลอง เข้าสู่ระบบ ระบบจะ ดึงกฎคะแนนเพื่อประมาณการ จาก D5 ประเภทขวด / กฎคะแนน จากนั้น บันทึกสแกน Guest ลงใน D4 บันทึกสแกน Guest และส่ง ผลสแกนทดลอง / ประมาณการแต้ม (ไม่ได้แต้มจริง) กลับไปยัง Guest

3.2.4.3 กระบวนการที่ 2.3 ตรวจสอบและอนุมัติภาพระบบ ดึงรายการรอตรวจสอบ จาก D2 ประวัติการทิ้งขยะ แล้วส่ง ข้อมูลภาพถ่ายรอตรวจสอบ ให้ ผู้ดูแลระบบ พิจารณา ผู้ดูแลระบบนำเข้า ผลการตรวจสอบ + แต้มปรับ (อนุมัติ / ไม่อนุมัติ / ขอภาพใหม่) เข้าสู่ระบบ จากนั้นระบบ อัปเดตสถานะรายการขยะ ใน D2 และ แจ้งผลการตรวจสอบ / แต้มที่ได้ กลับไปยัง สมาชิกทั่วไป หากอนุมัติแล้ว ระบบจะ เพิ่มแต้มสมาชิกเมื่ออนุมัติ ใน D1 ข้อมูลผู้ใช้งาน (users) และ บันทึกธุรกรรมแต้มเมื่ออนุมัติ ใน D3 ธุรกรรมแต้ม (เส้นประในรูปหมายถึงเกิดเมื่ออนุมัติแล้วเท่านั้น)

### 3.2.5 การออกแบบแผนภาพกระแสข้อมูล (Data flow Diagram level 1 of Process 3.0) ![](media/image10.png){width="4.47778980752406in" height="3.952777777777778in"}

**รูปที่ 3.5** Data Flow Diagram Level 1 Process 3.0 จัดการของรางวัล

จากรูปที่ 3.5 แผนภาพกระแสข้อมูลระดับ 1 (Data Flow Diagram Level 1) ของกระบวนการที่ 3.0 จัดการแต้มสะสม ของรางวัล และการแลก สามารถแตกเป็นกระบวนการย่อยได้ 3 กระบวนการ ได้แก่

3.2.5.1 กระบวนการที่ 3.1 จัดการของรางวัล (CRUD) ผู้ดูแลระบบ นำเข้า ข้อมูลเพิ่ม/แก้ไข/ลบของรางวัล (ชื่อ แต้มที่ใช้ สต็อก) เข้าสู่ระบบ ระบบจะ ดึงรายการของรางวัล จาก D3 ของรางวัล (rewards) แล้ว บันทึก/อัปเดตของรางวัล กลับไปยัง D3 พร้อมส่ง รายการของรางวัล / ผลการอัปเดต กลับไปยังผู้ดูแลระบบ

3.2.5.2 กระบวนการที่ 3.2 แลกของรางวัล สมาชิกทั่วไป นำเข้า คำขอแลกของรางวัล เข้าสู่ระบบ ระบบจะ ดึงแต้มสะสมสมาชิก จาก D1 ข้อมูลผู้ใช้งาน (users) และ ดึงของรางวัลและสต็อก จาก D3 ของรางวัล / การแลก / แต้ม เมื่อเงื่อนไขครบ ระบบจะ ตัดแต้มสมาชิก ใน D1 และ บันทึกรายการแลก + รหัสรับของ + ธุรกรรมตัดแต้ม ใน D3 จากนั้นส่ง รายการของรางวัล / รหัสรับของ / แต้มคงเหลือ กลับไปยังสมาชิกทั่วไป *(Guest แลกรางวัลไม่ได้)*

3.2.5.3 กระบวนการที่ 3.3 ยืนยันรับของด้วย QR / ยกเลิกการแลก ผู้ดูแลระบบ นำเข้า สแกน QR รับของ / คำสั่งยกเลิก ระบบจะ ดึงรายการแลกจากรหัส QR จาก D3 การแลกของรางวัล แล้วอัปเดตสถานะ (รับแล้ว / ยกเลิก) กลับไปยัง D3 พร้อมส่ง สถานะรับของสำเร็จ / ยกเลิกแล้ว ให้ผู้ดูแลระบบ และ อัปเดตสถานะการแลก / แต้มคืน (กรณียกเลิก) ให้สมาชิกทั่วไป หากยกเลิก ระบบจะ คืนแต้มเมื่อยกเลิก ใน D1 และ บันทึกธุรกรรมคืนแต้ม ใน D3 ธุรกรรมแต้ม (point_transactions) (เส้นประในรูป)

### 3.2.6 การออกแบบแผนภาพกระแสข้อมูล (Data flow Diagram level 1 of Process 4.0) ![](media/image11.png){width="4.47778980752406in" height="3.4519838145231847in"}

**รูปที่ 3.6** Data Flow Diagram Level 1 Process 4.0 ประมวลผลสถิติและรายงาน 

จากรูปที่ 3.6 แผนภาพกระแสข้อมูลระดับ 1 (Data Flow Diagram Level 1) ของกระบวนการที่ 4.0 ประมวลผลสถิติและรายงาน สามารถแตกเป็นกระบวนการย่อยได้ 3 กระบวนการ ได้แก่

3.2.6.1 กระบวนการที่ 4.1 ประมวลผลรายงานภาพรวมระบบ ผู้ดูแลระบบนำเข้า คำร้องขอดูรายงานสถิติ เข้าสู่ระบบ ระบบจะดึง จำนวนสมาชิก / แต้มรวม จาก D1 ข้อมูลผู้ใช้งาน, สถิติรายการขยะตามสถานะ จาก D2 ประวัติการทิ้งขยะ และ สถิติการแลกของรางวัล จาก D3 แต้ม ของรางวัล การแลก เพื่อประมวลผลแล้วส่ง รายงานสถิติปริมาณขยะและแต้มภาพรวม กลับไปยังผู้ดูแลระบบ

3.2.6.2 กระบวนการที่ 4.2 แสดงสถิติส่วนตัว สมาชิกทั่วไปนำเข้า คำร้องขอดูสถิติส่วนตัว เข้าสู่ระบบ ระบบจะดึง แต้มสะสม / โปรไฟล์ จาก D1 ข้อมูลผู้ใช้งาน, ประวัติการทิ้งขยะของสมาชิก จาก D2 ประวัติการทิ้งขยะ และ ประวัติแต้มและการแลก จาก D3 ธุรกรรมแต้ม / การแลก จากนั้นส่ง ข้อมูลกระดานสถิติส่วนตัว (แต้ม ประวัติสแกน การแลก) กลับไปยังสมาชิกทั่วไป

3.2.6.3 กระบวนการที่ 4.3 จัดการถัง ประเภทขวด และตั้งค่า ผู้ดูแลระบบนำเข้า ข้อมูลจัดการถัง / ประเภทขวด / กฎคะแนน เข้าสู่ระบบ ระบบจะ ดึงข้อมูลถังและตั้งค่า จาก D5 ถังขยะ / ประเภทขวด / ตั้งค่า (bins / plastic_types / settings) แล้ว บันทึก/อัปเดตถัง ประเภทขวด ตั้งค่า กลับไปยัง D5 พร้อมส่ง รายการถัง / กฎคะแนนที่อัปเดต กลับไปยังผู้ดูแลระบบ

##  3.3 การออกแบบระบบ (System Design)

การออกแบบระบบเว็บแอปพลิเคชัน EcoBin Connect ในงานวิจัยนี้ กำหนดสถาปัตยกรรมแบบแยกชั้น (Multi-tier Architecture) โดยแบ่งส่วนติดต่อผู้ใช้ ส่วนประมวลผล และส่วนจัดเก็บข้อมูลออกจากกันอย่างชัดเจน เพื่อให้สามารถพัฒนา ทดสอบ และเผยแพร่ระบบได้อย่างยืดหยุ่น รวมถึงรองรับการขยายจำนวนผู้ใช้งานในอนาคต

ระบบออกแบบให้ทำงานผ่านเครือข่ายอินเทอร์เน็ต โดยผู้ใช้เข้าใช้งานผ่านเว็บเบราว์เซอร์ ส่วนหน้าเว็บทำหน้าที่แสดงผลและรับข้อมูลจากผู้ใช้ จากนั้นส่งคำขอไปยังบริการ API เพื่อประมวลผลธุรกิจ และบันทึกหรือดึงข้อมูลจากฐานข้อมูลหลักบนคลาวด์
