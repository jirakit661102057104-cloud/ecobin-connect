# สรุปงานที่ทำ

เอกสารนี้บันทึกการเปลี่ยนแปลงหลักก่อนขึ้นระบบจริง ไม่รวมประวัติฟีเจอร์เก่าทั้งโปรเจกต์

## 1. กดรีเฟรชแล้วยังอยู่หน้าเดิม

เดิมแอปเป็นแท็บในหน้าเดียว ไม่มี URL แยก พอกดรีเฟรชจะเด้งกลับหน้าแรกตามบทบาท (แอดมินไปแผงควบคุม สมาชิกไปแดชบอร์ด)

**สิ่งที่ทำ**

- จำแท็บหลักใน `localStorage` ตามผู้ใช้
- จำแท็บย่อยแผงแอดมิน และแท็บย่อยประวัติ
- หลังโหลดสิทธิ์แล้วเปิดแท็บที่เคยอยู่ ถ้าแท็บนั้นใช้กับบทบาทนั้นได้

ไฟล์หลัก: `frontend/src/lib/navState.ts`, `frontend/src/App.tsx`, `AdminPanel.tsx`, `HistoryView.tsx`

## 2. เอาเมนูสลับบัญชีทดสอบออก

เมนูโปรไฟล์มุมขวาบนเคยมีรายชื่อบัญชีทดสอบให้กดสลับได้ ไม่เหมาะกับเว็บจริง

**สิ่งที่ทำ** ลบบล็อก «สลับบัญชีทดสอบ» ออกจาก `Header.tsx` เหลือข้อมูลบัญชี ตั้งค่า และออกจากระบบ

## 3. เก็บโค้ดขึ้น GitHub

โปรเจกต์ยังไม่มี commit ถูกเชื่อมกับ

https://github.com/jirakit661102057104-cloud/ecobin-connect

ไฟล์ลับไม่ถูกอัป เช่น `backend/backend.env`, `.env.local`

ใน PowerShell ต้องรันสคริปต์ด้วยจุดนำหน้า เช่น `.\deploy-cloud-run.bat` ไม่ใช่แค่ชื่อไฟล์

## 4. ขึ้นเว็บบน Vercel

Frontend เป็น Next.js อยู่ที่โฟลเดอร์ `frontend/`

- Root Directory ต้องเป็น `frontend`
- อย่าใส่ `GEMINI_API_KEY` / `APP_URL` ที่ Vercel ตรวจเจอจากไฟล์ตัวอย่าง AI Studio
- ค่าที่เว็บใช้: `NEXT_PUBLIC_GOOGLE_CLIENT_ID`, `NEXT_PUBLIC_DEMO_LOGIN=false`, `API_PROXY_TARGET`

ตอน build เคยพังที่ TypeScript (`motion` ไม่ได้ import, `SMART_BIN_LOCATIONS` ไม่มี) แก้แล้วบิลด์ผ่าน

## 5. Google Login: redirect_uri_mismatch

แอปส่งผู้ใช้กลับมาที่ `/login` ของโดเมน Vercel แต่ใน Google Cloud ยังอนุญาตแค่ localhost

ต้องใส่ Authorized JavaScript origins และ Authorized redirect URIs ให้ตรงโดเมนจริง ดูรายละเอียดใน [04-google-login.md](./04-google-login.md)

อย่าใส่ `GOOGLE_CLIENT_SECRET` บน Vercel

## 6. Failed to fetch (สมัคร / Google ไม่สำเร็จ)

หลัง Google ยอมแล้ว เว็บยังเรียก API ไม่ถึง เพราะยิงไปที่ `http://localhost:8080` ซึ่งคนอื่นบนอินเทอร์เน็ตเข้าไม่ได้

**สิ่งที่ทำ**

- บนโดเมนจริง เบราว์เซอร์เรียก `/api` ของเว็บเอง (same-origin)
- Vercel ส่งต่อคำขอไปยัง Go API
- ตัด `output: 'standalone'` ที่ทำให้ route `/api` บน Vercel เป็น 404

ข้อความ `Failed to fetch` จึงแปลว่า «เบราว์เซอร์คุยกับ API ไม่ได้» ไม่ใช่รหัสผ่านผิด

## 7. อุโมงค์ Cloudflare (ชั่วคราว เลิกใช้แล้ว)

เคยเปิด `cloudflared` ชี้พอร์ต 8080 บนเครื่อง เพื่อให้ Vercel เรียก API ได้ขณะทดลอง

ใช้ไม่ได้เป็นโหมดจริง เพราะดับเมื่อปิดเทอร์มินัล และ URL เปลี่ยนทุกครั้งที่เปิดใหม่ ตอนนี้เลิกใช้แล้ว

## 8. ย้าย API ไป Google Cloud Run

เพื่อให้รันตลอดเวลาโดยไม่เปิดโน้ตบุ๊ก

- บริการ: `ecobin-api`
- ภูมิภาค: `asia-southeast1`
- ต่อ Cloud SQL instance `ecobin-mysql` ผ่าน Unix socket (ไม่ต้องเปิด MySQL ออกเน็ตจาก Cloud Run)
- `min-instances=1` ไม่ให้บริการหลับ
- สคริปต์: `deploy-cloud-run.bat` → `deploy-cloud-run.ps1`

ตรวจสุขภาพ: เปิด `/health` ต้องได้ `{"status":"ok"}`

รูปที่อัปโหลดบน Cloud Run อยู่บนดิสก์ชั่วคราวของคอนเทนเนอร์ รีสตาร์ทแล้วรูปเก่าบนเซิร์ฟเวอร์นั้นอาจหาย ถ้าต้องการเก็บถาวรควรย้ายไป Cloud Storage ในรอบถัดไป

## 9. โดเมน jirakit.site

โดเมนที่ Hostinger พร้อมใช้ ยังไม่บังคับว่าต้องผูกทันที เว็บใช้โดเมน Vercel ได้เลย

ถ้าจะชี้ `jirakit.site` มาที่ Vercel ให้เพิ่มโดเมนใน Settings → Domains แล้วตั้ง DNS ตามที่ Vercel แสดง จากนั้นเพิ่ม origins/redirect ของ Google ให้ครบโดเมนใหม่
