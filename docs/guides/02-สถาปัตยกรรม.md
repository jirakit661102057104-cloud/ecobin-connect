# สถาปัตยกรรมระบบจริง

EcoBin Connect แยก 3 ส่วน คนละที่ ทำงานร่วมกันผ่าน HTTPS

```
ผู้ใช้ (เบราว์เซอร์)
  → จำแนกรูปด้วยโมเดล AI ในเครื่องผู้ใช้ (ขวด / กระป๋อง)
  → Vercel (Next.js หน้าเว็บ)
       → /api/* และ /uploads/* ถูกส่งต่อไป Cloud Run
            → Go API
                 → Cloud SQL (MySQL)
```

## หน้าที่ของแต่ละส่วน

| ส่วน | ที่อยู่ | ทำอะไร |
|---|---|---|
| หน้าเว็บ + AI ฝั่ง client | Vercel, โฟลเดอร์ `frontend/` | UI, กล้อง, จำแนกขวด/กระป๋อง, Google login ฝั่งเบราว์เซอร์ |
| API | Cloud Run, โฟลเดอร์ `backend/` | Auth, บันทึกขยะ, ให้แต้มทันที, คาร์บอน CMH/TGO, แอดมิน |
| ฐานข้อมูล | Cloud SQL MySQL `ecobin-mysql` | ผู้ใช้ ขยะ แต้ม รางวัล emission_factors จุดทิ้ง |

เว็บบน Vercel **รัน Next.js อย่างเดียว** ไม่รัน Go และไม่เก็บ MySQL

## การคุยกันของเว็บกับ API

บนเครื่องพัฒนา (`localhost`) เว็บเรียก `http://localhost:8080` โดยตรงได้ หรือใช้ proxy

บนโดเมนจริง เว็บเรียก path เดียวกันกับหน้าเว็บ เช่น `/api/auth/register` จากนั้น

1. Route `frontend/src/app/api/[...path]/route.ts` ส่งต่อไป `API_PROXY_TARGET`
2. ค่าปัจจุบันอยู่ใน `frontend/vercel.json` เป็น URL ของ Cloud Run
3. Cookie ที่ API ตั้งถูกส่งกลับผ่าน Vercel จึงอยู่โดเมนเว็บ

อย่าตั้ง `NEXT_PUBLIC_API_URL=http://localhost:8080` บน Vercel

## Flow ธุรกิจหลัก (ปัจจุบัน)

1. สมาชิกล็อกอิน (Google / อีเมล)
2. ถ่ายหรืออัปโหลดรูปขวดพลาสติกหรือกระป๋อง
3. โมเดลในเบราว์เซอร์จำแนก — รับเมื่อความแม่นยำ **> 80%**
4. กดบันทึก → API คำนวณคาร์บอน + **ให้แต้มทันที** (สถานะอนุมัติแล้ว)
5. แลกรางวัลได้จากแต้มสะสม — แอดมินยืนยันรับของ

Guest ทดลองสแกนได้ แต่ไม่ได้รับแต้มจริง

## ทำไมเคยพังเมื่อปิดเครื่อง

เดิม Go รันด้วย `run.bat` บนโน้ตบุ๊ก ปิดเครื่อง = API ตาย แม้ Vercel ยังเปิดหน้าเว็บได้

ตอนนี้ Go อยู่ Cloud Run ฐานข้อมูลอยู่ Cloud SQL ปิดโน้ตบุ๊กได้

## โปรเจกต์ Google Cloud ที่ใช้

Cloud SQL และ Cloud Run อยู่โปรเจกต์เดียวกับ instance ฐานข้อมูล

Connection name รูปแบบ:

`PROJECT_ID:asia-southeast1:ecobin-mysql`

บัญชีบริการของ Cloud Run ต้องมีสิทธิ์ `roles/cloudsql.client`
