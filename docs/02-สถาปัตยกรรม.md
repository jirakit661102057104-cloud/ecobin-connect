# สถาปัตยกรรมระบบจริง

EcoBin Connect แยก 3 ส่วน คนละที่ ทำงานร่วมกันผ่าน HTTPS

```
ผู้ใช้
  → Vercel (Next.js หน้าเว็บ)
       → /api/* และ /uploads/* ถูกส่งต่อไป Cloud Run
            → Go API
                 → Cloud SQL (MySQL)
```

## หน้าที่ของแต่ละส่วน

| ส่วน | ที่อยู่ | ทำอะไร |
|---|---|---|
| หน้าเว็บ | Vercel, โฟลเดอร์ `frontend/` | UI, ล็อกอิน Google ฝั่งเบราว์เซอร์, ส่ง cookie เซสชัน |
| API | Cloud Run, โฟลเดอร์ `backend/` | สมัคร, ล็อกอิน, สแกน, แต้ม, แอดมิน, ตรวจ token Google |
| ฐานข้อมูล | Cloud SQL MySQL `ecobin-mysql` | เก็บผู้ใช้ ขยะ ของรางวัล |

เว็บบน Vercel **รัน Next.js อย่างเดียว** ไม่รัน Go และไม่เก็บ MySQL

## การคุยกันของเว็บกับ API

บนเครื่องพัฒนา (`localhost`) เว็บเรียก `http://localhost:8080` โดยตรง

บนโดเมนจริง เว็บเรียก path เดียวกันกับหน้าเว็บ เช่น `/api/auth/register` จากนั้น

1. Route `frontend/src/app/api/[...path]/route.ts` หรือ rewrite ใน `next.config.ts` ส่งต่อไป `API_PROXY_TARGET`
2. ค่าปัจจุบันอยู่ใน `frontend/vercel.json` เป็น URL ของ Cloud Run
3. Cookie ที่ API ตั้งถูกส่งกลับผ่าน Vercel จึงอยู่โดเมนเว็บ ไม่ติดปัญหา CORS ข้ามโดเมนเท่าการยิง API ตรงจากเบราว์เซอร์

อย่าตั้ง `NEXT_PUBLIC_API_URL=http://localhost:8080` บน Vercel

## ทำไมเคยพังเมื่อปิดเครื่อง

เดิม Go รันด้วย `run.bat` บนโน้ตบุ๊ก ปิดเครื่อง = API ตาย แม้ Vercel ยังเปิดหน้าเว็บได้

ตอนนี้ Go อยู่ Cloud Run ฐานข้อมูลอยู่ Cloud SQL ปิดโน้ตบุ๊กได้

## โปรเจกต์ Google Cloud ที่ใช้

Cloud SQL และ Cloud Run อยู่โปรเจกต์เดียวกับ instance ฐานข้อมูล (ไม่ใช่โปรเจกต์ชื่อ `ecobinconnect` ที่ตอนแรกยังไม่มี instance)

Connection name รูปแบบ:

`PROJECT_ID:asia-southeast1:ecobin-mysql`

บัญชีบริการของ Cloud Run ต้องมีสิทธิ์ `roles/cloudsql.client`
